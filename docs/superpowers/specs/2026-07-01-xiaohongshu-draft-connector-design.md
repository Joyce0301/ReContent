# 小红书草稿连接器设计

日期：2026-07-01

## 背景

ReContent 当前已经完成从内容输入、URL 抽取、Prompt 构建、多平台生成到结果展示的主流程，但在真实使用场景里，用户在拿到小红书成稿后，仍然需要手动打开小红书创作页、粘贴标题正文、补充标签，再自行保存草稿。

这一步会明显拉长“生成内容 -> 进入发布流程”的路径，也削弱产品作为内容生产工具的真实可用性。

本次设计目标是在不依赖小红书官方公开发布 API 的前提下，让用户可以从 ReContent 直接跳入小红书创作页，并自动预填可 review 的草稿内容。

## 目标

第一版实现一个“发送到小红书草稿”的连接能力：

- 用户在 ReContent 中生成小红书内容后，可点击按钮进入小红书创作流程
- 如果本机浏览器中已登录小红书创作后台，则自动打开创作页并预填标题、正文、标签建议
- 如果未登录，则跳转到小红书登录页，并提示用户登录后重新发起
- 整个流程只做到“进入编辑页并预填内容”，最终保存草稿或发布仍由用户在小红书页面内完成

## 非目标

第一版明确不做以下内容：

- 不接入账号密码登录
- 不保存或托管小红书 cookie / 登录态
- 不自动点击正式发布
- 不支持图片上传、封面上传、定时发布、合集、地点、商品等高级发布能力
- 不支持团队成员共享同一个小红书账号的远程自动发稿
- 不承诺纯云端 SaaS 环境可直接使用

## 用户场景

目标用户为内容创作者或小型自媒体工作室成员，已在本机浏览器中使用小红书创作后台。

典型路径如下：

1. 用户在 ReContent 中输入原文或 URL，生成小红书版本内容
2. 用户在结果页查看生成稿，并确认标题与正文基本可用
3. 用户点击“发送到小红书草稿”
4. 系统调用本机浏览器连接器：
   - 已登录：打开小红书创作页并自动填充内容
   - 未登录：打开登录页，并提示用户完成登录后再次操作
5. 用户在小红书页面中进行最终 review，并选择保存草稿或继续补充内容

## 产品定义

### 功能入口

在小红书结果视图中新增主操作按钮：

- `发送到小红书草稿`

该按钮与现有复制能力并列，但语义明确区分：

- 复制：用户自己手动粘贴
- 发送到小红书草稿：系统帮助用户进入创作页并预填内容

### 用户心智

第一版产品心智定义为：

> ReContent 帮你把生成内容快速送进小红书创作页，但最终审核、保存草稿和发布动作仍由你完成。

这一定义必须在交互文案中保持一致，避免用户误解为“已经替我正式发出”。

## 预填字段范围

第一版自动预填以下字段：

- 标题：使用当前小红书结果中的标题
- 正文：使用当前小红书结果中的正文，保留换行与段落
- 标签建议：优先作为正文尾部附加，或整理为可见建议区供用户确认

第一版暂不自动处理：

- 图片上传
- 封面图上传
- 视频笔记
- 多图笔记排序
- 商品、地点、合集、权限设置
- 定时发布

封面文案建议可以继续在 ReContent 内生成和展示，但不作为第一版自动注入目标。

## 技术方案

### 总体结构

采用“Web 端内容生成 + 本机浏览器自动化桥接”的架构。

分层如下：

1. ReContent 前端
2. 小红书连接器（本地桥接 / 浏览器自动化层）
3. 小红书创作页

### ReContent 前端职责

- 在小红书结果卡片中显示“发送到小红书草稿”按钮
- 将当前结果整理为结构化 payload
- 调用本地桥接动作
- 根据桥接返回结果展示状态提示
- 在失败时回退为可复制流程

建议 payload 结构如下：

```ts
type XiaohongshuDraftPayload = {
  sourceId: string;
  title: string;
  content: string;
  tags: string[];
};
```

### 本地桥接职责

本地桥接负责：

- 打开或切换到本机浏览器
- 导航到小红书创作入口
- 判断当前是否处于登录状态
- 登录状态成立时，定位标题和正文输入区并填充内容
- 登录状态不成立时，打开登录页并返回“未登录”结果

第一版不要求自动点击“保存草稿”按钮，优先停留在已填充好的编辑页面。

### 为什么不用纯前端网页实现

普通 Web 页面无法稳定操作另一个域名下已登录页面的 DOM，浏览器同源策略会阻止这类访问。因此：

- 不能仅靠前端 `window.open(...)` 实现自动填充
- 需要借助浏览器自动化、本地助手或浏览器扩展等桥接能力

本设计的第一版选择“本机浏览器自动化桥接”，因为它最接近目标体验，同时开发量低于独立扩展和桌面端助手。

## 用户流程

### 已登录路径

1. 用户点击 `发送到小红书草稿`
2. 前端将 `title/content/tags` 发送给本地桥接
3. 本地桥接打开小红书创作页
4. 桥接确认用户已登录
5. 桥接找到编辑区并自动填充标题和正文
6. ReContent 提示：
   - `已打开小红书编辑页，请检查内容后保存草稿`

### 未登录路径

1. 用户点击 `发送到小红书草稿`
2. 本地桥接打开小红书登录页或创作页登录态检查页
3. 如果判断为未登录，返回未登录状态
4. ReContent 提示：
   - `请先登录小红书，登录完成后重新发送`

第一版允许用户登录后再次点击按钮，不要求自动恢复之前那次草稿注入流程。

## 状态与错误处理

### 前端状态

建议定义如下状态：

- `idle`
- `opening`
- `login_required`
- `filled`
- `unsupported_page`
- `failed`

### 失败场景与处理

1. 创作页打不开
   - 提示用户检查网络，或手动打开创作后台后重试

2. 用户未登录
   - 跳转登录页，并提示登录后重新发起

3. 页面结构变化，无法找到输入框
   - 提示“小红书页面结构已变化，当前无法自动填充”
   - 提供复制按钮作为兜底

4. 标题或正文超限
   - 在发送前本地校验
   - 如果超出限制，不发起自动填充，提示用户先在 ReContent 中调整

5. 自动化中断
   - 保留原始生成稿
   - 用户仍可通过复制方案手动发布

## 风控与安全边界

第一版必须满足以下边界：

- 不读取用户账号密码
- 不存储登录态 cookie
- 不自动正式发布
- 不在无明确用户点击的情况下自动跳转和操作
- 所有跨站页面操作仅限用户本机环境

这不仅是实现约束，也是产品信任边界。用户需要明确知道产品是在“辅助草稿编辑”，而不是“接管账号发布”。

## UI 与文案建议

### 按钮文案

- 主按钮：`发送到小红书草稿`

### 点击前提示

- `将在你本机浏览器中打开小红书创作页，并自动填入当前内容`

### 成功提示

- `已打开小红书编辑页，请检查内容后保存草稿`

### 未登录提示

- `请先登录小红书，登录完成后重新发送`

### 自动化失败提示

- `当前无法自动填充，你仍可复制内容后手动粘贴到小红书`

## 兼容性与限制

- 第一版默认支持桌面浏览器环境
- 更适合个人账号或小团队成员在自己的电脑上使用
- 页面依赖小红书创作后台现有 DOM 结构，因此后续需要维护选择器
- 第一版不保证多浏览器、多系统组合下全部一致

## 成功标准

第一版完成的判定标准：

- 小红书结果视图中可见“发送到小红书草稿”入口
- 已登录用户点击后能进入创作页并看到标题和正文已被填充
- 未登录用户点击后能被引导到登录页，并得到明确提示
- 自动化失败时用户仍可通过复制完成工作流
- 不发生自动正式发布
